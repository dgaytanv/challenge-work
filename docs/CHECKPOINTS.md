## Reading this table

- **in this branch** -- the file is here, under `models/<name>/` or `checkpoints/candidates/`, with a
  `.sha256` beside it. Its digest matches the digest recorded by the run that produced the number.
- **durable store** -- on this box under `~/hackathon-shared/checkpoints/c2/`, digest-verified after
  copy. Not in this branch, usually because it is one of three seeds of a configuration that is not a
  finalist.
- **training scratchpad** -- the file still exists at the path the run recorded, but nothing protects
  it. A branch checkout deleted candidate checkpoints from a working tree twice during the campaign.
- **GONE** -- the recorded path no longer resolves. The number stands (it is in a JSON with its
  provenance) but the checkpoint cannot be re-scored.
