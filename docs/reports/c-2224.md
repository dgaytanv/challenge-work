## What shipped

Code, all on `wp-c` and all used by WP-D's candidate arms:
- **Two-view consistency loop** — clean + degraded views concatenated on the batch dim, one forward
  through preproc and encoder, consistency on the **latent** (what the grader's probe reads).
  `two_view: false` reproduces stock training **bit-for-bit** (max |ΔCE| = 0.000e+00 over 19 steps).
- **Centred cosine** (`62a5c8e`) — the uncentred version was measuring nothing and rewarding the
  pathology it hid.
- **Population-normalised MSE** (`b362571`) — scale-free; the raw form's effective weight grew with the
  latent norm through the run.
- **`val_bn_batch_stats`** (`c9c0a6f`, default-on `d6dd0fe`) — WP-D's two-view run had early-stopped on a
  corrupted val head and shipped an epoch-1 encoder. Their arms depend on this.
- **Shuffled-pair control**, geometry logging, JSD term, `aux/` checkpoint dir, guarded acceptance test.

## The one measured row, and it is negative

`c-twoview-cos1`: **mean_area 0.7712 ± 0.0034**, clean AUC 0.8370 (`runs/c-twoview-cos1_20260903_220316.json`).
Tie with the stock anchor, **-0.0206 against the mask fix on frozen weights**, and clean AUC -0.0235
outside standing ruling 3 with no compensating gain.

The loss is **one family**: rect -0.0458 vs anchor, with **AUC 0.3901 at s=1.0 — below chance, the probe
is inverted**. In four of five families run 1 loses *less* with severity than the anchor. It traded clean
AUC for robustness and broke rect. Both fixes are separable and neither was run.

Run 2 (centred) and run 3 (reweight) were cut at convergence. **This package ships one negative row plus
the fixes the winning arms depend on.**

## Untested prediction, first thing to run next
Run 1's uncentred cosine had a measured incentive to inflate the shared latent offset (loss falls 190x from
offset 0 to 90); the centred cosine is exactly offset-invariant. So run 2's `lat_offset` should sit near
stock's 0.17x rather than run 1's 30.46x → 37.54x → 36.31x. Command and config pinned in writeup §2.5.
