## 1. The fit question, and the number campaign 1's figure is NOT

**Campaign 1's 15,735,808 is the multiply *count per event* of the UNFOLDED design**, where every multiply is
its own piece of hardware. It is not the hardware count of the folded design, and quoting it as one overstates
the cost by two orders of magnitude. What the folded design actually **instantiates**, read from the emitted
`firmware/parameters.h` (`quant/fit_estimate.py` → `quant/g7_fit_g6b_N400_pf1.json`), not assumed:

| block | multipliers instantiated | |
|---|---|---|
| `phi_0` 14→128 | 1,792 | per-token datapath: |
| `phi_1` 128→128 | 16,384 | built **once**, |
| `score` 128→32 (fused q·k, R1) | 4,096 | iterated 400 times |
| `v` 128→128 | 16,384 | |
| — per-token subtotal — | **38,656** | |
| `combine` (attn·v einsum, ReuseFactor 400) | 512 | once per event |
| `out_proj` (4 seeds, `n_partitions = 1` → all four unrolled) | **65,536** | once per event |
| `bottleneck` 512→6 | 3,072 | once per event |
| **TOTAL INSTANTIATED** | **107,776** | |

**The fold is 146× on hardware: 15,735,808 → 107,776.** That is the difference between a design that cannot
exist and one in the same order of magnitude as the part.

### Against `xcvu13p-flga2577-2-e`: 12,288 DSP48E2, 1,728,000 LUTs, 200 MHz

* 107,776 multipliers is **8.8× the DSP count**. Most must be LUT logic regardless — which is the normal
  outcome for 7-bit × 8-bit operands, since a DSP48E2 is 27×18 and is wasted on them. Not a problem, but it
  means the DSP budget is not the binding constraint; LUTs are.
* At **25–60 LUTs per small fixed-point multiplier** — a range on purpose; a point estimate here would be
  false precision — that is **2.7 M – 6.5 M LUTs against 1.73 M**. **So as configured, `pf = 1` probably does
  NOT fit.** I would rather say that now than let the number look better than it is.
* **`out_proj` alone is 61 % of the multipliers, and for no good reason.** Its input is `[4, 128]`, so
  `out_width = 4` and hls4ml gives it `n_partitions = 1` — all four seed positions unrolled. Folding it the
  same way as the token loop (`ParallelizationFactor = 1`; a one-line config change, **not** applied in the
  running synthesis) takes the total to **58,624 → 1.5 M – 3.5 M LUTs**, straddling the budget.
* Beyond that, `ReuseFactor` on `phi_1` and `v` is the remaining dial: `rf = 4` takes each from 16,384 to
  4,096 and the total to ~34,000 multipliers, at 4× the token-pass cycles.

**The honest summary: the fold turned an impossible design into a dial.** Where on that dial it fits is
exactly what the running C-synthesis is for; the proxy says `pf = 1` is over and `out_proj` is the first thing
to fold. Multiplier counts above are exact; the LUT figures are a proxy and are not a synthesis result.

### Latency
With `pf = 1` the token pass is **400 sequential iterations = 400 cycles = 2.00 µs at 200 MHz**, which bounds
the initiation interval. Total latency adds the depth of the dataflow chain (the 400-wide softmax reduction
and the tail), which is not knowable without the synthesis. Folding `out_proj` costs 3 more cycles; `rf = 4`
on `phi_1`/`v` would take the token pass to 1,600 cycles = 8 µs. Not measured — stated as what the structure
implies.

## 2. Future work item, from the §2 attribution
The phase Vitis is stuck in is dominated by the **N-independent tail quantizers**: `norm_pooled_iq` and
`bottleneck_iq` are ~77.8 k LLVM instructions each, because hls4ml spends ~152 instructions per `ap_fixed`
conversion and the 512-wide tail has 1,024 of them. **The next thing to change is therefore the tail
quantization, not anything to do with tokens**: quantize *before* the flatten (so the quantizer sees a
`[4, 128]` tensor with a foldable leading axis), or give the 512-wide tail a per-tensor quantizer instead of
a per-channel one, either of which cuts that generated code by up to ~512×. Both are **model** changes with
an accuracy cost that would have to be measured, not assumed — and §8c.2's result (per-tensor activations are
a 3-seed tie with per-channel) says the per-tensor variant is likely to be free. Recorded in the writeup's
"what does not work yet" as item 1.
