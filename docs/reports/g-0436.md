## 3. G6b — **the token loop folds, and it took no new code in the model**
Campaign 1's blocker was that io_parallel at N=400 unrolls every per-token layer 400 times. Reading the
hls4ml source rather than guessing: `hgq.layers.QDense.parallelization_factor` (default −1 →
`prod(shape[1:-1])`, i.e. 400 copies) → `QDenseHandler` copies it into the layer config → `multi_dense.py`
rewrites the Dense as a Conv1D carrying it → `vivado_backend.init_conv1d` sets
`n_partitions = out_width // pf`. Setting **pf = 1** therefore gives one per-token datapath iterated 400
times, with the same weights and the same arithmetic.

**Evidenced in the emitted C++, not asserted** (`synth/prj_g6b_N400/firmware/parameters.h`):

| layer | before (campaign 1) | now |
|---|---|---|
| `phi_0`, `phi_1`, `score`, `v` | fully unrolled over 400 tokens | `n_partitions = 400`, `n_pixels = 1` (×4) |
| `combine` (attn·v `QEinsum`) | 204,800 multipliers | `reuse_factor = 400`, **`multiplier_limit = 512`** |
| `softmax` | pf = 32 | pf = 1 |

The einsum does not take a `parallelization_factor`, but its template emits
`#pragma HLS PIPELINE II = reuse_factor` and `ALLOCATION mul limit = total/reuse_factor`, so `ReuseFactor` is
its fold knob; that is what the 512 above is.

* **Conversion at N=400 now takes 6 s** (campaign 1: converted, then failed to compile in 45 min).
* **N=16, pf=1, C-simulation vs Keras: max|d| = 0.000e+00, 100.00 % of elements exact**
  (`quant/g6_g6b_N16_pf1.json`). The fold changes nothing numerically, as designed.
* **C-synthesis at N=400 has been running since 04:02** (34 min so far), currently past the dataflow checks.
  Expected: unknown — that is the experiment. 3 h cap per the brief; I will report the partial log if it hits.

## 4. G6a — the homogeneity constraint, first two seeds, and a result I did not expect
Six QAT runs are in flight through `gpu_slot.sh` (3 seeds × {homogeneous, heterogeneous}); the heterogeneous
arm is a like-for-like control because campaign 1's operating point exists at **one** seed only and its
±0.0005 is a probe std, not a seed std, so it cannot enter a seed test. Seed 11 of each is done (≈5.5 min/run):

| | EBOPs (N=200) | distill rms | distill max&#124;d&#124; | mask margin |
|---|---|---|---|---|
| `g6a-het-bits6-relu-l1t-s11` (per-channel) | **3.806e8** | 0.2893 | 2.0412 | 60.2 e-folds |
| `g6a-hom-bits6-relu-l1t-s11` (per-tensor) | **3.981e8 (+4.6 %)** | 0.2893 | 2.0412 | 60.2 e-folds |

Three metrics identical to four decimals is exactly the signature this project has learned to distrust, so I
checked the two parameter files element by element instead of believing it:
* 133 of 199 tensors are **bit-identical** — including every kernel and bias;
* 45 differ only in **shape** (the homogeneous quantizers are per-tensor: e.g. `phi_0`'s data-lane triple is
  `(1,1,1)` against `(1,1,14)`);
* 21 differ in value, and they are the EBOPs counters plus the weight bit-widths `b`, whose largest
  disagreement is **0.087** — under half a bit, so they round to the same integer.

The mechanism, from the exported triples: the homogeneous quantizer takes **i = max over channels**
(e.g. `phi_0`: heterogeneous i ranges −6…7 per channel, homogeneous i = 7 for all). Same fractional bits
(f ≈ 5.76 → 6 everywhere, pinned at the cap), wider integer range. A wider range can only *remove*
saturation, never add rounding error, so the arithmetic comes out identical and the cost is bits.

**Provisional reading, to be confirmed on the ruler:** at a 6-bit cap, HGQ2's per-channel activation
granularity buys **resources, not accuracy** — homogeneity costs **+4.6 % EBOPs and nothing measurable
on the outputs**. I will not state this as the finding until the three-seed benches are in; two runs
agreeing bit-for-bit is a hypothesis with a mechanism, not a measurement.
