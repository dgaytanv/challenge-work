### `bench_eval.py`
- `--seed N` records the checkpoint's **training** seed in the JSON. Falls back to the train
  config's `seed` hyperparameter, and records `null` if neither exists. `seed_source` says which
  (`flag` / `train_cfg` / null) so a claimed seed is distinguishable from an inferred one.
  Like `--train_data` it is a **claim by the caller**, not something bench_eval observes — it does
  not seed anything here, and the probe stays deliberately unseeded because its spread is the
  measurement.
- `encoder_params` / `encoder_params_trainable`: counted from the built encoder, so unlike seed it
  is **observed**. Needed for "ties go to the smaller model"; no JSON in `runs/` carried it before.
  Counts the encoder only — not the preprocessor or the projector/classifier, which the grader
  never runs.

### `ablation_table.py`
New **Per-configuration** section above the existing tables. Groups on
`(config, regime, suite)` where config is the tag without its `-s<seed>` suffix, regime is
`train_data`, and suite separates pf/l1t × scoring/heldout/colleague × full. Reports seed mean,
**seed std**, n with the seed list, the mean per-seed probe std, clean AUC, params, and the
pre-registered seed test against `--seed-reference`. Keeps `[RETRACTED]` handling and the
two-floor note.

### `compare_arms.py`
`--seeds` switches the unit of evidence from the run to the configuration and uses the seed std.
Default mode is untouched.

## Two real defects the fixture caught before any real run

Both are register failure class 1 (grouping on too few fields), in new places, and both produced a
confident-looking number rather than an error.

1. **The seed table read `n=1` for every configuration.** `latest_per_tag()` collapses rows before
   the seed section saw them, so three seeds filed under one tag — legal, since the `seed` field
   distinguishes them — silently became one row. The seed table now reads the unfiltered runs and
   de-duplicates on `(config, regime, suite, seed)` itself.
2. **`compare_arms --seeds` silently mixed data regimes.** It compared a full-file candidate
   against the **small-file** reference (0.8185 instead of 0.8260) and printed a confident ratio,
   which is precisely what rule 5 forbids. It now filters by regime and **refuses** an ambiguous
   comparison instead of resolving it:
   `AMBIGUOUS -- h-champion-full spans [...]. Pass --regime <train_data> to choose.`
