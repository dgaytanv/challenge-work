## Where the drift actually lives

`tests/latent_subspace_decomposition.py`, severity 0.5, 20k events. Train the grader's own EvalMLP
on clean latents, linearise it per event (`g = d(class margin)/dz`), split `d = z_d - z_c` along
`g_hat` and orthogonal to it. Hypothesis was WP-C's; this is the measurement.

| | clean-trained | aug-trained |
|---|---|---|
| population spread | 1.2953 | 1.9489 |
| total drift / spread | 0.856 | 0.726 |
| **d_par / spread** (probe-relevant) | **0.211** | **0.261** |
| d_perp / spread (null-space) | 0.810 | 0.653 |
| harmful fraction, squared magnitude | 0.112 | 0.201 |
| AUC clean | 0.8868 | 0.8915 |
| AUC on `z_c + d_perp` | 0.8860 | 0.8869 |
| AUC on `z_c + d_par` | 0.8556 | 0.8677 |
| AUC on full `z_d` | 0.8560 | 0.8628 |

The decisive line is the operational one: on the clean-trained model the null-space component is
**3.8x larger** than the probe-relevant one and costs **0.0008** AUC, while the small probe-relevant
component costs **0.0312** and reproduces the entire degradation cost. Two readings agree, one
first-order and one not.

**Consequence.** An MSE on raw displacement weights by squared magnitude, so ~89% of its gradient
budget goes on motion costing ~2.5% of the AUC loss.

**And augmentation does not fix this.** It shrank the harmless component and grew the population
spread 50%, but `d_par/spread` went *up*, 0.211 -> 0.261. Its +0.0147 mean_area looks like it comes
from separating the classes relative to the drift, not from invariance in the direction that matters.
That is the gap the planner's JSD logit-consistency term is meant to close.

**Caveats, kept deliberately.** The probe direction comes from a probe I fit on this model's clean
latents, not the grader's refit, so `g` is a faithful proxy rather than the exact operator. Across
two probe inits the harmful fraction read 0.282 then 0.268 — conclusion stable, third digit not.

## Bug caught before it produced a number
WP-C's `c1a548c` adds `<name>_encoder_<ts>_bestauc.pth` and `_last.pth`. Both match the glob my
benches used to select a checkpoint, and `_last` is rewritten every epoch, so it always wins `ls -t`.
Every bench from that point would have silently scored the last epoch instead of best-val-loss and
looked entirely normal. Fixed by excluding `_(bestauc|last)\.pth$`; caught before any affected run
finished, and flagged to WP-C since anyone automating checkpoint selection has the same exposure.
