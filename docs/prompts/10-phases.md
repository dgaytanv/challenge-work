# Phases, integration, and rulings

## Phase 1 (now, four instances in parallel, target 3-4 hours)
| WP | Owns | First milestone | Depends on |
|----|------|-----------------|------------|
| A | models.py (TransformerEncoder) | mask-fix bench on the stock checkpoint, 30 min | nothing |
| B | degradation.py | tests pass and histogram, 60 min | nothing |
| C | training.py, loss.py, train.py, train_config.yaml | two-view loop runs in test_mode, 60 min | placeholder degradation (in the prompt) |
| D | new encoder classes in models.py, encoder_class key in train.py | Deep Sets clean bench, 90 min | nothing |

File ownership avoids merge conflicts: A and D both touch models.py but in different classes; D adds one config read in
train.py that C also edits (a one-line merge). The placeholder degradation is identical text in A, C and D so early results
are comparable; it is thrown away when B merges.

GPU: one A10. Full runs are serialised by gpu_run.sh, so expect a queue. Order of priority if several are waiting:
C's first two-view run, then B's augmentation run, then A's readout variants, then D (D's runs are short).
Test-mode runs do not need the lock.

## Phase 2 (after Phase 1 reports, target 2-3 hours)
1. Planner merges to `integration`: A's mask fix and best readout, B's generator, C's two-view loop.
2. C retrains the integrated primary model with B's generator (tag `int-primary-v1`) and benchmarks with `--full`.
3. D rebases onto integration, retrains the best set encoder with the two-view loop and B's generator (tag `int-deepsets-v1`).
4. A becomes WP-E: sweeps on the integrated primary model, one variable at a time: latent_dim {6, 16, 32}, contrastive_weight
   {0.05, 0.5}, consistency_weight {1, 3}, batch_size {128, 256}. Then optional add-ons in this order: DisCo penalty between the
   latent and the dropped-pt fraction; an auxiliary head predicting the dropped-pt fraction per coarse cell; EMA clean teacher.
5. B becomes WP-F: adversarial/worst-case region selection (pick the rectangle among 8 candidates that maximises latent shift)
   and a held-out corruption family not in the bench (e.g. rotated ellipses) to test generalisation honestly.

## Convergence (final 1-2 hours)
- Every candidate checkpoint benchmarked with `--full`. Table: tag, clean AUC, per-family area, mean_area.
- Ruling by the planner on the final architecture. If the set encoder wins or ties, final models.py aliases
  `TransformerEncoder` to it with defaults set so eval.py needs no config changes.
- If two models are close, try latent-level concatenation inside one wrapper class (both encoders in one nn.Module; latent_dim
  is the concatenation) and benchmark that too.
- Final branch `submission`: run the organisers' `eval.py` end to end from a fresh clone before calling it done.
- Writeup material: the literature review, the anchor vs final curves per family, the ablation table (mask fix alone,
  augmentation alone, two-view alone, all together).

## Phase-1 run protocol (ruled 20:15, applies to every full run)
num_epochs 25, batch_size 256, early_stopping_patience 5, mixed precision on, WP-B generator from `integration`
(the placeholder is retired: it dropped ~3% of candidates on average). DeepSets / PMA(L=0) runs (<1 GB) may run
without the GPU lock; everything else queues through gpu_run.sh in the order C, B, A, E. Final acceptance runs
(eval.py at batch 1024 needs ~8 GB free) are serialised through gpu_run.sh and never overlap training.

## Standing rulings
1. The bench maps are never used for training. Any instance that wants a new bench family asks the planner.
2. The organisers' private files under `~/hack-data/C9_robust_tagging` (anything not `train/*.pt`, `eval/*.pt`,
   `checkpoints/*.pth`) are off limits.
3. Keep clean AUC within 0.02 of the anchor unless mean_area gains more than 0.03; otherwise flag it.
4. Every reported number comes from `bench_eval.py` with the JSON in `runs/`. No hand-computed numbers.
5. Results are reported as measured, including regressions.
6. Every two-view or drift report includes a shuffled-pair cosine control on ITS OWN encoder (raw and centred); the offset
   pathology is general but its size is architecture-specific (30x on the transformer, 3.9x on Deep Sets).
8. Probe refits alone move clean AUC by ~0.0015 (A, same checkpoint, same events); differences below that are noise.
   Two-view reports log centred cosine AND its shuffled-pair floor; a matched cosine at the floor means identity is gone.
9. The probe in eval.py/bench_eval.py is unseeded (init and shuffle), so every mean_area is a refit; bench_eval now reports
   mean +- std over --probe_repeats (E, 21:25) and no ruling between arms is made below the measured 3-sigma floor.
   MEASURED (E, 21:35, stock transformer, 20k, 10 refits on frozen embeddings): mean_area sigma 0.0008, 3-sigma = 0.0025;
   clean AUC sigma 0.0006. Errors are correlated across families (one frozen probe), so never divide by sqrt(5).
   Deep Sets floor pending from D. Mask fix = 23 sigma, deepsets-aug vs anchor = 56 sigma, 20k-vs-full gap = 2.4 sigma.
10. Runs are compared on mean_area and eval-set latent geometry, never on val AUC: val AUC sees the projector in eval mode
    where a common latent offset is visible, while the training gradient never saw it (A, 21:35).
7. Objective changes are made only after a measurement that motivates them is in reports/ (e.g. A's probe-drift decomposition).
